Advanced checks

Normal saves use the fetched ETag. Snapshots are independent: no write retries, automatic merges, or cross-panel ETag updates.

  1. Permissions: create as Alice and save the demo sharing preset. Bob can edit, Carol can only read, and Dana can edit through the strongest matching grant. Only the owner can delete or manage sharing; the server, never the demo label, decides.
  2. Stale saves: keep a second snapshot, save the main editor, then save the second snapshot. Expect 412 with its draft and ETag preserved. Load the latest in the other editor, preserve your changes, then reload and reconcile explicitly.
  3. Preconditions: expand a note's request options. Omit If-Match for 428; try W/"1", *, or "1", "2" for 400. A stale "1" gives 412.
  4. Revocation: use separate tabs for Alice and Bob. After Alice saves Make private, Bob's new reads return 404 and his old save must fail (404, or 412 for a racing save). Already returned content cannot be recalled.
  5. Validation: use custom sharing JSON for duplicate grants or unknown teams. Rejected replacements must not change grants or version. Paging should never show inaccessible or duplicate notes.
